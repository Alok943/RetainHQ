## Headline finding (why extend, not accept-as-is)

The pre-existing seed was **production-skill-first**: it opened at Async Python → FastAPI and
never taught the Python *language*. But "Python for backend" Round-1 screens hammer language
internals — `is` vs `==`, mutable default args, decorators, generators, dunder methods, the GIL,
shallow vs deep copy. A candidate who can wire FastAPI but can't explain why
`def f(x, items=[])` is a bug fails the screen before the framework round.

**Change:** prepend three phases (Language Core → Pythonic Constructs → OOP) ahead of the
existing production phases, and fold the old scattered Pydantic/error nodes into their proper
phases. Net: 40 → **69 topics**, 5 → **8 phases**, strict prerequisite order preserved.

## Step 2 — Concepts ranked by hiring signal (ordering device, no invented stats)

Highest separation between pass/fail candidates, in rough order:
1. Mutability & object identity (`is`/`==`, mutable-default bug) — the fastest tell of "learned
   Python" vs "learned to prompt Python".
2. Decorators + generators + context managers — the "do you think in Python idioms" trio.
3. GIL / threading-vs-multiprocessing / async — every backend screen probes concurrency.
4. OOP data model (dunders, MRO, `@property`) — framework code assumes it.
5. ORM footguns (N+1, session lifecycle) — the on-the-job differentiator.
Framework routing syntax ranks LOWER than the above — it's googlable; the language reasoning is not.

## Final topic table (69 nodes, 8 phases) — see `seed_python_backend.py` for the tuples

- **1 · Python Language Core** (13) — Objects & Identity: mutable-vs-immutable · `is` vs `==` ·
  None & truthiness · variables-as-references. Collections: list vs tuple · dict internals &
  ordering · set & membership · comprehensions · slicing. Functions & Scope: *args/**kwargs ·
  mutable-default pitfall · closures & LEGB · positional-vs-keyword args.
- **2 · Pythonic Constructs** (8) — iterators & the protocol · generators & yield · generator
  expressions · decorators · `functools.wraps` · context managers (`with`) ·
  try/except/else/finally · custom exceptions & EAFP.
- **3 · OOP in Python** (8) — class vs instance attributes · instance/class/static methods ·
  `@property` · dunder methods (`__eq__`/`__hash__`) · `__str__` vs `__repr__` · inheritance &
  `super()` (MRO) · duck typing · dataclasses.
- **4 · Concurrency, Memory & Performance** (9) — concurrency vs parallelism · the GIL ·
  threading vs multiprocessing · coroutines async/await · the event loop · tasks & gather ·
  blocking-calls-in-async pitfall · reference counting & GC · shallow vs deep copy.
- **5 · Web Framework & API** (12) — WSGI vs ASGI · path & query params · request body &
  response_model · routers & app structure · async vs def endpoints · dependency injection
  (Depends) · middleware & CORS · status codes & OpenAPI · background tasks · Pydantic models &
  validators · pydantic-settings · ConfigDict & from_attributes.
- **6 · Data Layer** (7) — SQLAlchemy/SQLModel async · sessions & expire_on_commit · eager
  loading (selectinload) · N+1 queries · Alembic migrations · transactions & atomicity ·
  connection pooling.
- **7 · Testing** (6) — pytest basics & fixtures · parametrized tests · mocking & patching ·
  async tests · API tests (httpx/TestClient) · coverage & CI.
- **8 · Production & Deployment** (6) — env vars & secrets (12-factor) · structured logging ·
  HTTPException & error shape · Dockerfile & multi-stage builds · uvicorn/gunicorn workers ·
  health checks, rate limiting & JWT/CORS.

Tier curve: Phase 1–2 skew easy; hard topics (`expire_on_commit`, `selectinload`, blocking-in-
async) cluster in phases 4/6. No phase opens on a `hard` topic.

## Step 6 — adversarial review, criticisms accepted (exactly one revision)

1. **Language front entirely missing** (original seed) → prepended Phases 1–3. *Primary fix.*
2. **Pydantic as its own phase** taught before any web context → merged into Phase 5.
3. **Error-handling split** across a standalone "Errors & Logging" phase → language-level
   exceptions moved to Phase 2 (EAFP), HTTP-level error shape to Phase 8.
4. **`try/except` never taught** yet EAFP/custom exceptions assumed → added to Phase 2.
5. **Production phase was 7 nodes of medium sameness** → compressed to 6, folded rate-limiting +
   JWT/CORS into one "hardening" node (they're one interview beat, not three).
6. **No memory-model node** despite "how does Python GC work" being a stock question → added
   reference counting & GC to Phase 4.

## Prerequisite-order / rule violations found in the ORIGINAL seed (extend-mode flags)

- **Opened on `hard`-adjacent async material** with no language foundation → violated "never open
  on hard" + prerequisite order. Fixed by front phases.
- **"The GIL" taught in Phase 1** (Async) but referenced by threading decisions never introduced →
  regrouped under Concurrency with threading-vs-multiprocessing beside it.
- **"Pydantic → v2 → Settings" as a standalone phase** before the web layer → reordered after
  routing so validators have a request to validate.
- No topic was a pure umbrella; the old `recall_hint`s were already answer-shaped (kept verbatim
  where the node survived).
